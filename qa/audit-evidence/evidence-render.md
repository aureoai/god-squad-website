## How the page works (runtime facts, verified in support.js and live)
- The HTML is a Claude Design "dc" document: all visible markup sits inside a custom <x-dc> element; a <helmet> child holds the Google Fonts <link> and the only <style> block; a <script type="text/x-dc" data-dc-script data-props="..."> holds `class Component extends DCLogic { renderVals() {...} }` returning products[] and values[] (the data), plus a `currency` editor prop (enum ₱/$/€, default ₱).
- support.js: hideRawTemplate() injects `x-dc{display:none!important}` synchronously; loadReactUmd() appends React 18.3.1 and ReactDOM 18.3.1 production UMD from unpkg.com with SRI hashes (async=false); then boot() parses <x-dc> innerHTML as a template, evaluates the data-dc-script with `new Function(...)` (DCLogic is an alias of the runtime's StreamableLogic class), compiles <sc-for list="{{ products }}" as="p">, <sc-if value="{{ p.img }}">, `{{ p.name }}` interpolations and `style-hover` attributes, replaces <x-dc> with <div id="dc-root"> and renders with ReactDOM.createRoot. The helmet manager clones the <link>/<style> nodes into <head>.
- boot() also re-fetches location.href and re-renders from the raw text (the HTML document is requested twice per load). On file:// that second fetch fails silently; the page still boots.
- If unpkg is unreachable (offline, ad-blocker, proxy, SRI mismatch) the catch only logs and rethrows; the hiding style is never removed, so the ENTIRE page stays blank (announcement bar, hero, nav and footer are all inside <x-dc>).
- `style-hover` IS implemented: collectProps() turns any `style-*` attribute into a pseudo-class rule; createPseudoSheet() inserts `.scp0:hover{background:rgb(42,40,35)!important;color:rgb(243,239,230)!important}` and `.scp1:hover{background:rgb(230,211,166)!important;color:rgb(13,12,10)!important}` into a head stylesheet and adds classes scp0/scp1 to the two CTAs. Verified live. (An earlier lead claim that hover was dead was WRONG and must not appear in the audit.)
- `data-r`, `data-screen-label`, `hint-placeholder-count`, `hint-placeholder-val` are editor metadata / CSS hooks; the runtime does not act on data-r or data-screen-label.
- The runtime attaches no event handlers of its own; only `on*` attributes in markup would be wired, and the markup has none. There is no menu toggle, cart, search or any interaction beyond native anchor behaviour and the two CTA hover rules.
- Template delimiters are `{{ }}` — the same as Shopify Liquid. Pasting this markup into a Liquid section would make Liquid evaluate `{{ products }}`, `{{ p.name }}` etc. as undefined and output empty tiles.
- The x-import / Babel path (@babel/standalone 7.29.0 from unpkg) exists in the runtime but is not used by this page.

## Network and console on load (served over HTTP)

- Two 404s on every load: GET /%7B%7B%20p.img%20%7D%7D and GET /%7B%7B%20v.icon%20%7D%7D. Cause: the browser parses the raw <img src="{{ p.img }}"> and <img src="{{ v.icon }}"> inside <x-dc> before the runtime replaces them. Harmless visually; disappears once the markup is ported.
- /favicon.ico -> 404 (no favicon of any kind).
- No other console errors or warnings.
- External origins at runtime: unpkg.com (React, ReactDOM; Babel only if x-import were used), fonts.googleapis.com (CSS), fonts.gstatic.com (font files). Preconnect exists only for fonts.googleapis.com and lacks crossorigin; none for fonts.gstatic.com or unpkg.
